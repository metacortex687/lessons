Состав команд, предусловия, постусловия в целом совпадают с эталонным решением.

У меня нет метода `size()`, но есть два метода `count()` и `capacity()`. Поскольку использую фиксированный массив, то решил контролировать вместимость через интерфейс.

И значит метод `put()` имеет дополнительное предусловие, что есть место для ключа. Называю `set` - появилось новое слово, хотя можно было бы использовать `put`, как и в других заданиях.

Также добавлен метод `can_set`, который возвращает возможность добавления значения по ключу. Можно добавить, если есть место в таблице, это может быть, если такой ключ уже есть или размер таблицы ещё меньше вместимости таблицы.

В реализации определения вхождения ключа `is_key` обнаружил возможную ошибку. Проблема следствие используемых двух типов пустых значений ячеек массива, один это пустое значение при инициализации, другой пустое значение после удаления элемента. И для поиска значения использовал приватный метод, который ищет ячейку для вставки. Для вставки подходит любой из этих пустых типов ячеек, но в случае поиска при обнаружении пустого значения от удаления элемента надо продолжать поиск. На курсе по АСД этот метод приватный параметризовал для поиска ячейки для вставки и поиска вхождения элемента, в этом решении решил, что проще сделать два разных цикла с немного разными условиями без переиспользования кода.

Сделал тесты, с помощью тестов убедился в наличии ошибки и поправил.

Как следствие, вывод, что в случае если ассоциативный словарь используется достаточно долго, когда элементы добавляются и удаляются, так что весь массив будет заполнен пустыми значениями после удаления, то алгоритмическая сложность получения значения сильно уменьшится с O(1) до O(N), где N это размер массива.
