#### Выбор языка

В прошлом задании пытался подобрать язык для выполнения работ по курсу. Python не нравится динамической типизацией, теряются плюсы статической типизации.

В Go нет частично реализованных классов. Можно наследовать интерфейсы, но нельзя наследовать структуры.

Rust - улучшенная версия Go. Очень удобен для проектирования. Но также нет частично реализованных классов. Есть интерфейсы, интерфейсы можно наследовать. В интерфейсах можно задавать предопределённые методы, которые используют исключительно методы интерфейса. Но в дальнейшем интерфейсы надо реализовать для структуры данных. При этом поля в структурах данных могут быть скрытыми, аналог приватных полей классов. 

В Rust явное деление на команды и запросы, через `&mut self` и `&self`.

TypeScript наиболее близок к примерам из уроков. Его и буду использовать для выполнения заданий. Есть возможность создавать тесты.

Rust интересен для прототипирования, при этом то, что будет реализовано на Rust, можно почти один в один перенести в TypeScript. Это будут абстрактные классы без полей данных. Обратное уже не получится, так как нет наследования структур данных и нельзя повторно использовать поля структур.

Выбрал TypeScript.

#### Рефлексия по реализации

В прошлом уроке попробовал сделать реализацию АТД, при этом для Node использовал структуры данных, что неверно, надо было использовать классы с методами и запросами.

Если при проектировании классов учитывать и эффективность реализации, то если это односвязный список, в котором есть right() и нет метода left(), поскольку right() — O(1), а left() — O(N), то логично по этим же причинам не использовать и put_left() в односвязном списке.

Само описание предусловий и постусловий в целом совпадает. У меня немного больше предусловий, возможно избыточно. При этом детализирую ошибки, например для поиска это: ListEmpty и CursorOnTail. Посчитал, что поскольку поиск начинается со следующей справа позиции курсора, то это будет ошибка. Можно было просто выводить, в статусе поиска, что ничего не найдено.

Для is_head() и is_tail() добавил предусловие, что список не пуст. Так как посчитал, что для того, чтобы ответить да или нет, у курсора должна быть позиция, а она имеет смысл только не в пустом списке.

Были сделаны варианты решения на Python, Go, Rust. В дальнейшем буду использовать TypeScript.

Еще одна из причин — желание повторно использовать реализацию одних и тех же АТД и на фронтенде, и бэкенде. Предполагаю, это сильно упростит взаимодействие, в отличие когда бэкенд был на Python, а фронтенд на React (JS).
