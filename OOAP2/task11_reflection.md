
Реализовал класс `CNone`. Проверку типов выполняю с помощью `mypy` командами вида `uv run --with mypy  mypy "OOAP2\task11.py" `.
Проверка типов строгая, запустил во время написания рефлексии типов, пришлось скорректировать решение [OOAP2\task11.py](OOAP2\task11.py)

Для того чтобы не надо было делать проверку типов, `CNone` переопределяет все родительские методы на новые. и можем их вызывать, только они ничего не будут делать.
```python
     def return_none(self, *args, **kwargs):
            return None
```

В конструкторе, кодом вида:
```python
	cls = type(self)

	for base in cls.__mro__[1:]:
		for name, value in vars(base).items():
			if isfunction(value) and not name.startswith("__"):
				setattr(cls, name, return_none)
```

Команды однозначно можно переопределять, соответственно тип None ничего не делает. В случае запросов, возвращается None, и значит, потенциально будут проверки на None и возвращаемся к тому, с чего начали.

Оставлять не  переопределёнными, считаю неправильным, так как возможен вызов методов и поведения которое не должно быть.

Еще надо отслеживать 'листья' Если наследование `A<-B`,то тип `CNone` будет наследоваться от `B`: `A<-B<-CNone`, если вдруг появился потомок `C`, тогда уже `A<-B<-C<-CNone`, а наследование от `C` надо убрать, то-есть нарушается принцип OCP, так как надо модифицировать.
